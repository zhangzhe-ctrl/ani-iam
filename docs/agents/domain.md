# Domain Docs

本文件规定 engineering skills 在探索和修改本仓库前如何使用领域文档。

## 探索前读取

- 阅读仓库根目录的 `CONTEXT.md`
- 阅读 `docs/adr/` 中与当前事项相关的 ADR
- 阅读当前事项、其直接阻塞事项，以及事项明确引用的当前规格或核心计划

如果某个文件不存在，继续工作，不要仅因缺失而预先创建。`domain-modeling` 会在新的术语或决策真正确定后按需更新这些文件。

## 文档布局

本仓库使用 **single-context** 布局：

```text
/
├── CONTEXT.md
├── docs/adr/
├── docs/plans/
└── .scratch/ani-iam-rebuild/
```

根目录 `CONTEXT.md` 是共享领域词汇表，`docs/adr/` 保存已接受的架构理由。实施事项不能把计划文件或历史材料当成新的领域权威。

## 使用词汇表语言

事项标题、实现名称、测试名称、评审结论和错误说明必须使用 `CONTEXT.md` 定义的术语。不要漂移到词汇表明确列入 `_Avoid_` 的同义词。

如果所需概念不在词汇表中，先判断它是无意引入的新术语，还是确实存在的领域缺口；真实缺口交给 `domain-modeling` 处理。

## 处理 ADR 冲突

如果事项或实现与现有 ADR 冲突，必须明确指出冲突及理由，不能静默覆盖。需要改变已接受决策时，先修订或新增 ADR，再继续实现。
