本模块以编号前缀文件组织分层部署清单：`00-registry.yaml.tmpl` 创建 `ani-cutover-current` 与 `ani-cutover-target` 两个隔离命名空间并启动 registry pull canary；`10-storage.yaml.tmpl` 定义跨 namespace 的 PersistentVolumeClaim 及写入探针 Job，用于验证底层块存储；`20-network.yaml.tmpl` 通过默认拒绝 NetworkPolicy + 仅放行同 namespace 互访与 kube-dns 的策略，配合 echo Service/Deployment 与 network-runner Pod 完成网络连通性验证；`30-runtime.yaml` 是已渲染的最终清单，在各自 namespace 内以单副本 Recreate Deployment 拉起 postgres、redis、nats、auth/gateway（current）或 iam/gateway（target）等容器，并通过 Secret/ConfigMap 注入数据库 URL、JWT 私钥、OIDC discovery 等配置。每个资源均带 `cutover-fitness-id: CF-01` 与 `run-id` 标签以便按演练批次隔离。`.Dockerfile` 文件（ani-iam、current-auth、gateway、probe）提供构建这些镜像的 Dockerfile 供上层 CI 使用。
