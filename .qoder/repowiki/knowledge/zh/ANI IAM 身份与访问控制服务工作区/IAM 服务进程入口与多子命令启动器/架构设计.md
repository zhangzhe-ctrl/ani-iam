本模块是 `cmd/server` 下的单一 Go 包，承担进程级装配职责：
- `main.go` 作为唯一入口，通过 `os.Args[1]` 分派到多个一次性子命令（`begin-tenant-snapshot`、`provision-tenant-broker`、`install-workload-registry`、`provision-first-administrator`、`provision-workloads`），其余路径进入正常服务启动流程；使用 `flag` 解析 `-conf` 配置路径，借助 Kratos `config` 从文件与 `KRATOS_*` 环境变量加载 `conf.Bootstrap`。
- `app.go` 实现 `buildApp` 装配管线：初始化 PostgreSQL (`pgxpool`) 与 Redis 连接池并 Ping 校验、加载 Ed25519 私钥与 OIDC 客户端密钥、构建 JWX access-token codec、目标操作注册表、登录限流器、API Key 用量聚合器、OIDC provider/usecase、认证/授权 usecase、租户与平台管理 service、BOSS 身份集成、通知 gRPC 客户端与工作协程、可观测性中间件等，最终通过 `kratos.New` 注册 gRPC、Admin HTTP、Readiness、Observability 以及两个后台 worker（`apiKeyMaintenanceWorker`、`passwordActionNotificationWorker`）为 transport.Server 一并交由 Kratos 生命周期管理。
- `provision_workloads.go` 提供独立的一次性工作负载引导 CLI，严格校验 manifest SHA-256、CA 证书与 DSN 文件权限/大小限制，调用 `biz.WorkloadBootstrap` 完成幂等 provision 并输出 receipt。
- 依赖方向单向向外：仅依赖 `internal/conf`、`internal/biz`、`internal/data`、`internal/server`、`workloadregistry`、`sdk/grpcworkload`，不反向被业务层引用；所有外部资源（DB、Redis、TLS、OIDC、gRPC）均在 `buildApp` 中集中创建并通过函数参数注入，便于测试替换。
