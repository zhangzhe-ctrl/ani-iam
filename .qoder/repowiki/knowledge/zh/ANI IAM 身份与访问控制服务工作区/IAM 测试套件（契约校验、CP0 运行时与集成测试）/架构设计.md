测试按职责划分为三个并列子目录，彼此独立且通过 Go build tag 控制编译：
- `tests/contracts/`：纯静态契约测试，不依赖外部服务。`contracts_test.go` 通过加载 `api/iam/v1/iam_descriptor.pb` 与 `artifacts/core_tenant_integration_v1_descriptor.pb` 中的 protobuf FileDescriptorSet，用 `protoreflect` 枚举服务与方法清单，断言 IAM/Core 暴露的服务集合、消息字段集、错误枚举值与 gRPC Code 映射；同时以 `protojson.UnmarshalOptions{DiscardUnknown: false}` 对 `fixtures/*.v1.json` 做严格 round-trip，并用 `contract_pins.json` 锁定各 WR 版本（WR19~WR23）、工具链（buf/protoc-gen-go*）、通知模块、OpenAPI 工件与 fixture 清单的 SHA256。
- `tests/cp0/`：针对 CP0 进程的最小化集成，使用 Kratos 框架在内存中启动 gRPC/Admin 服务器，动态生成 ed25519 CA 与双向 TLS 证书，验证 `/healthz`、`/readyz`、`/metrics`、gRPC Health Check 及日志中间件输出 trace_id。
- `tests/integration/`：所有文件带 `//go:build integration` 标签，需显式 `go test -tags=integration` 运行。共享基础设施集中在 `wr20_fixture_test.go`（`wr20Environment`、`newWR20Environment`、Dex 反向代理、Postgres/Redis 容器化）、`formal_runtime_test.go`（正式 IAM + Gateway 进程编排）与 `session_test_support_test.go`（可插桩的 throttle/issuer）。每个场景文件（如 `oidc_*_test.go`、`password_*_test.go`、`tenant_*_test.go`、`wr20_*_test.go`）围绕同一环境组装业务用例，并通过 `recordReference` 写入 JSONL 审计记录。
- 顶层 `password_action_workload_identity_test.go` 与 `password_login_source_ip_contract_test.go` 为无 build tag 的轻量单元测试，仅依赖本地包。
