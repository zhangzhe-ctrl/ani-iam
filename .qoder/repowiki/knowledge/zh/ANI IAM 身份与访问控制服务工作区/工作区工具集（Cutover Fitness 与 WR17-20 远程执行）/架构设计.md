本模块按独立工作区划分目录：`cutover-fitness/` 是纯 Python 工具，`cf01.py` 通过 `argparse` 子命令 `render`/`validate` 对 Kubernetes 清单做模板替换与安全策略检查（禁止 NodePort/LoadBalancer、限定命名空间、强制镜像 digest、要求 `cutover-fitness-id: CF-01` 与 `run-id` label），`probe.py` 提供 TCP/UDP echo 服务器、存储往返、DNS 解析与 HTTP 登录冒烟测试，作为 CF-01 探针镜像入口；`wr17-18/`、`wr19/`、`wr20/` 各自包含一套相同的脚本骨架：`README.md` 描述运行约束，`remote-run.py` 负责在 SSH 到 `ubuntu@i-8yg2l7u8` 上创建隔离 run 目录、基于 `baseline.json`/`*-scope.json`/`*-initial-source.json` 校验源仓库 commit/tree、打包并上传源码 tar.gz，再在远端用 `verify-source.py` 校验文件模式/哈希后以独占锁 (`heavy.lock`) + GOMAXPROCS=2/-p=2 执行 `command.sh`，并通过 exit code 73/75/76 区分锁占用、内存不足与其他构建冲突；`generate.sh` 在指定 Go/sqlc/buf/atlas 版本下生成 SQL/Proto/Atlas 产物并二次重放比对；`wr20/` 额外提供 `stage-a/b/c.sh`、`checks-a.sh`、`collect.py`、`verify-ab.sh` 等阶段化流水线脚本，用于分阶段迁移与验证。依赖方向单向：各 `remote-run.py` 仅依赖标准库与本地证据目录 `.scratch/.../evidence/...`，不反向引用产品代码。
