# 29: 按精确清单退役旧身份资产与数据

**Status:** needs-info

**Type:** task

**Blocked by:** 28

**阶段与能力：** M2 之后的独立资产退役；R04，不是 M1/M2 的暗含前置。

**授权边界：** 计划票，尚未领取。每个资产/数据删除、Credential 失效及其他难恢复动作都要求精确人工确认；旧票、M1/M2 通过和本票创建均不构成确认。

## 目标

在系统已由 IAM 接管后，根据精确清单处理不再需要的旧运行资产、数据与凭据，并满足删除后仍适用的已接受恢复、安全审计和保留约束。

## 范围与非目标

- 先只读盘点旧库表/测试数据、deploy/runtime、Credential/Secret、镜像/配置与备份等候选资产；逐项记录 owner、消费者、保留理由、精确标识/环境、影响与可恢复性。
- 给每项拟执行动作形成可审阅删除/失效清单、保留列表、恢复 artifact/验证记录、人工确认和操作后检查；无消费者的结论必须有当前输入证据，不能只按名称推断。
- 满足适用的删除后恢复门禁与至少 180 天审计保留等已接受不变量。若确需额外持续恢复交付，先建立独立、具体、经接受的前置事项并更新依赖，不能复用已退役 cutover-window 材料。
- 仅执行最终精确确认的目标，保留所需证据与恢复资产；不把代码可恢复性当成数据库/凭据可恢复性。
- 非目标：替用户批准删除、直接扩大到生产、清理其他服务/租户业务数据、实现全新通用 DR 平台或宣称 Production Ready。

## 固定输入与工作面

- M2 接受输入、目标资产完整标识/UID/数据库范围、当前消费者证据、恢复/保留政策及具体 artifact 摘要：`not_frozen`。
- 精确 Allowed/Forbidden paths、环境/资源清单、每项动作和对应人工确认：`not_frozen`。本票阻塞只针对拟执行动作的实际缺口，不反向否定已完成的 M1 接口能力。
- 读取 [能力矩阵](../capability-matrix.md)、[决定表](../decisions.md) 与 WR-28；不能把旧 WR-14 的候选 long-term DR 方案自动视为已接受目标。

## 验收与验证

1. 清单逐项标记保留/删除/失效/未执行，owner 与当前消费者检查完备；任何无精确确认或恢复门禁未通过项不得执行。
2. 已确认动作后，必需系统接口与管理/审计能力回归通过；保留政策和适用恢复可用性有真实证据，未删项及未验证项如实列出。
3. 记录精确目标、操作时间、结果与脱敏证据；无范围外资产受影响，无额外 production-ready 声明。

## 恢复与停止

按已接受的逐项恢复方案执行，不能承诺不存在的逆操作。发现资产共享、实际消费者、确认目标不匹配、审计保留或恢复证据不足，立即停止相关动作并保留现场；任何新目标重新形成精确清单和适用确认。
